# TKT-379 — Regression Coverage For Interzonal Model Phase 1

- Typ: Applikation
- Priorität: P1
- Status: Planned

## Problem
The interzonal Phase 1 change touches scenario schema, KSE UI, engine routing, dispatch settlement, KPI composition, and round-result presentation. This creates a broad regression surface.

## Ziel
Protect the new model and critical existing flows with targeted regression tests and scenario smoke coverage.

## Umsetzung
- Add validation tests for zonal synthetic distributions in `environment.groups` and `market.consumer_mix` plus new grid settings.
- Add engine tests for:
  - one-zone fallback,
  - two-zone balanced import/export,
  - three-zone indirect path routing,
  - binding links,
  - unserved demand,
  - constrained-off generation,
  - each generator curtailment mode.
- Add KPI tests verifying grid constraint cost remains separate from imbalance.
- Add round-result payload tests for `zone_results`, `link_results`, and `player_zone_info`.
- Add frontend smoke checks for zone status and link utilization display.

## Akzeptanzkriterien
- Multi-zone routing and shortage scenarios are covered by automated tests.
- One-zone and legacy scenarios remain functional.
- Player-type zone assignment and legacy `general.player_zone` fallback are both covered by tests.
- Grid constraint cost is explicitly tested as a distinct settlement component.
- Player-facing zone status information is covered by smoke or component tests.
