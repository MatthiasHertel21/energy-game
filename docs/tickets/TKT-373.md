# TKT-373 — Player UI For Variable Bid Counts

- Typ: Applikation
- Priorität: P1
- Status: Planned

## Problem
Die Player-Oberfläche ist heute fest auf drei Lots A/B/C mit statischem Preisblock, `activeLot`-Logik und einem Drei-Serien-Overview ausgelegt.

## Ziel
Die Player-UI bildet `bid_count=0..5` pro Device konsistent ab, ohne Sonderlogik pro konkreter Lot-Anzahl zu duplizieren.

## Umsetzung
- Ersetze die starre A/B/C-Darstellung durch Rendering über eine dynamische Lot-Liste.
- `bid_count=0`:
  - kein Preisfeld
  - kein Bid Overview
  - klassische Geräteansicht mit einer Mengenreihe
- `bid_count=1`:
  - genau ein Preisfeld
  - kein Bid Overview
  - eine explizite Mengenreihe
- `bid_count=2..5`:
  - entsprechende Anzahl Preisfelder
  - editierbarer Lot-Fokus
  - Bid Overview als gestapelte Summenansicht aller Lots
- Generalisiere Default-Preislogik, Initialisierung, aktive Lot-Auswahl, Mengen-Synchronisierung und Aggregation `deviceHours`.
- Stelle sicher, dass DA-Baseline und Current Position auch bei variabler Lot-Anzahl korrekt angezeigt werden.

## Akzeptanzkriterien
- Player sieht pro Device exakt die konfigurierte Anzahl an Preisfeldern.
- `bid_count=0` und `bid_count=1` zeigen keinen Bid Overview.
- `bid_count=2..5` zeigen einen funktionierenden gestapelten Bid Overview.
- Mengenänderungen bleiben konsistent zwischen Lot-Ansicht und aggregierter Gerätesumme.
- Alte `bid_count=3`-Szenarien verhalten sich visuell wie bisher.
