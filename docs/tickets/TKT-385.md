# TKT-385 — Regression Coverage And Rollout Gate For Zonal Pricing V1

- Typ: Applikation
- Priorität: P0
- Status: Planned

## Problem
The main delivery risk is hidden drift in one-zone and no-split behavior. Top-level price checks are not sufficient; full visible outputs need coverage and rollout guardrails.

## Ziel
Add golden-case coverage and rollout blockers so V1 cannot ship if it changes one-zone or no-split behavior.

## Umsetzung
- Add or update backend regression tests for `zones = 1`, multi-zone no-split, split, losses, and shortfall, plus at least one complex 3-5-zone topology (partial coupling, islanding, or multiple binding links).
- Add API assertions for zonal payloads and no-split canonicalization, including canonical enum and flag semantics for `price_source`, `zonal_pricing_active`, and `player_zone_split_active`.
- Compare full visible outputs, not only top-level prices, for the golden cases. Block on drift in canonical legacy business values; additive informational no-split loss fields are allowed when they do not alter existing market, KPI, or settlement values.
- Document and wire a feature toggle for rollout safety. The toggle is a scenario-level flag `general.zonal_pricing_v1_enabled` (boolean, default `false`); the zonal path only activates when this flag is `true` AND `grid.zones > 1`. Document the flag name and activation condition in `docs/SPRINT_27_PLAN.md` and in the KSE help text.
- Keep the restore path to commit `7948f1c4a` explicit in release planning.
- Define rollout blockers for any drift in one-zone or no-split cases.

## Akzeptanzkriterien
- Golden cases fail on any drift in existing one-zone or no-split business values; additive informational no-split loss fields do not fail the gate by themselves.
- Split cases are covered for zonal prices, losses, separate shortfall costs, and at least one complex multi-zone topology.
- Release documentation contains a toggle-based fallback (`general.zonal_pricing_v1_enabled = false`) and a verified restore path.
- The feature toggle name and activation logic are documented and consistent between backend, KSE, and release notes.
- Sprint 27 cannot be marked done while regression blockers remain open.
