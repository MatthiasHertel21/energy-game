# TKT-371 — Scenario And Forecast Compatibility For Variable Bid Counts

- Typ: Applikation
- Priorität: P1
- Status: Planned

## Problem
Die bestehende Persistenz und API-Logik geht stillschweigend von einem booleschen Multi-Bid-Modus und festen Lots A/B/C aus. Ohne Kompatibilitätsschicht drohen Brüche bei Bestands-Szenarien, Forecasts und DA-Baselines.

## Ziel
Szenario- und Forecast-Daten unterstützen variable Bid-Anzahlen je Device, ohne alte Daten unlesbar zu machen.

## Umsetzung
- Ergänze ein Device-Feld `bid_count` im Szenario-Modell.
- Halte die bestehende Forecast-Struktur `device_id -> lot_label -> {price, hours}` vorerst bei, erweitere aber die zulässigen Lots auf `A..E`.
- Entferne die fachliche Abhängigkeit von `market.enable_player_bidding` im Submit- und Ladepfad.
- Implementiere eine Kompatibilitätsschicht beim Lesen:
  - alte Szenarien mit `enable_multi_bid=true` -> `bid_count=3`
  - alte Szenarien mit `enable_multi_bid=false` oder ohne Feld -> `bid_count=0`
  - alte Forecasts mit Lots `A/B/C` bleiben gültig
- Stelle sicher, dass DA-Baselines, gespeicherte Forecasts und zusammengesetzte Bid-Payloads auch mit `1`, `4` oder `5` Lots korrekt verarbeitet werden.

## Akzeptanzkriterien
- Alte Szenarien können ohne manuelle Migration geladen werden.
- Alte Forecasts mit A/B/C bleiben lesbar.
- Neue Szenarien können `bid_count` je Device setzen.
- DA-Baseline- und Forecast-APIs liefern für variable Lot-Anzahl konsistente Payloads.
