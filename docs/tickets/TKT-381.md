# TKT-381 — Deterministic Zonal Clearing And No-Split Canonicalization For V1

- Typ: Applikation
- Priorität: P0
- Status: Planned

## Problem
The current engine clears the commercial market globally and only applies network logic afterward. That cannot produce zonal prices while preserving exact current behavior for one-zone and no-split cases.

## Ziel
Implement a deterministic zonal merit-order clearing with ATC limits for V1 and canonize all visible values back to the global reference result whenever no actual price split exists.

## Umsetzung
- Introduce `clear_market_coupled_atc(...)` as a deterministic zonal merit-order clearing path.
- Build supply and demand books per zone.
- Allow trade from cheaper export zones to more expensive import zones while **price spread is positive** and ATC remains available.
- Recompute zonal marginal prices and flows after each relevant trade step.
- Compute `system_price`, `zone_prices`, `zonal_pricing_active`, zonal cleared volumes, link flows, and residual unserved demand.
- Remove the `general.player_zone` fallback from engine bid-building (`_build_player_zone_and_role_maps`); V1 uses only `player_types[].zone`.
- Keep the existing global clearing path unchanged for `zones <= 1`.
- Run a global reference clearing for `zones > 1` and use it as the canonical source for all visible values when `zonal_pricing_active = false`.
- Treat losses only as quantity reduction and separate reporting, not as an independent split trigger.
- Slim down `_compute_interzonal_round_outputs(...)`; zonal surplus/deficit logic is replaced by `zone_net_position_mwh` from the new clearing; keep only residual curtailment and informational network outputs.
- Restrict `apply_grid(...)` in the zonal path to residual curtailment only; do not use `cong_signal` as a price or rent driver.
- Ensure `da_dispatched_mwh` per device retains its zone context when carried over from DAM to IDM clearing; capacity checks in the IDM phase must be performed per zone.

## Akzeptanzkriterien
- `zones = 1` still uses the current global clearing behavior without visible drift.
- Multi-zone no-split cases keep all visible market values identical to the global reference clearing.
- Split cases produce stable zonal prices and ATC-constrained interzonal flows.
- Positive losses alone do not trigger a price split.
- The engine does not fall back to `general.player_zone` for any V1 scenario.
- No new external dependency (SciPy or similar solver) is introduced.
