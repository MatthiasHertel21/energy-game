# TKT-370 — KSE Per-Device Bid Count Configuration

- Typ: Applikation
- Priorität: P1
- Status: Planned

## Problem
Die aktuelle Szenario-Konfiguration koppelt das Bietverhalten an einen globalen Multi-Bid-Schalter und ein boolesches Device-Override. Dadurch sind nur die Modi "klassisch" oder "3 Lots A/B/C" möglich.

## Ziel
Designer können im KSE pro Device die Anzahl der Angebote auf 0 bis 5 festlegen. Der globale Scenario-Schalter entfällt.

## Umsetzung
- Ersetze `market.enable_player_bidding` im KSE durch ein per-device Feld `bid_count`.
- Ersetze `enable_multi_bid` in DeviceCards durch eine numerische Eingabe oder Select für `0..5`.
- Definiere die fachliche Bedeutung im KSE klar:
  - `0`: implizites Angebot zu variablen Kosten bzw. impliziter WTP
  - `1`: ein explizites Preisfeld, kein Bid Overview
  - `2..5`: entsprechende Anzahl expliziter Preisfelder, Bid Overview aktiv
- Validierung im KSE für gültige Integer-Werte zwischen 0 und 5.
- Rückwärtskompatible Darstellung bestehender Szenarien:
  - bisheriges `enable_multi_bid=true` wird als `bid_count=3` interpretiert
  - bisheriges `enable_multi_bid=false` oder nicht gesetzt wird als `bid_count=0` interpretiert

## Akzeptanzkriterien
- Im KSE gibt es keinen globalen Multi-Bid-Schalter mehr.
- Jedes Device hat genau ein konfigurierbares Feld `bid_count` mit Werten `0..5`.
- Bestehende Szenarien bleiben im Editor ladbar und werden plausibel auf das neue Modell abgebildet.
- Die KSE-Validierung verhindert ungültige Werte außerhalb `0..5`.
