# TKT-384 — Player UI And Detail Views For Zonal Pricing V1

- Typ: Applikation
- Priorität: P1
- Status: Planned

## Problem
Player-facing views and detail tables currently assume a single global market price. Without explicit UI work, split cases would be hard to understand and no-split cases could regress visually.

## Ziel
Expose zonal pricing clearly in split cases while keeping default screens unchanged for one-zone and no-split scenarios.

## Umsetzung
- Keep current default pricing presentation unchanged when `zonal_pricing_active = false`.
- Show local `zone_price`, optional `system_price`, and price spread only when a real split exists.
- Extend round results with zonal price, zone context, and link visibility for split cases.
- Update detail views and debug-oriented tables to use the same price semantics as backend settlement.
- Show shortfall as a separate scarcity or balancing component, not as a replacement market price.
- Ensure market overview and scenario results surface zonal aggregates consistently.

## Akzeptanzkriterien
- One-zone and no-split UI states remain visually and numerically aligned with current behavior.
- Split cases clearly show the player's local zone price and relevant link context.
- Detail views do not contradict top-level KPI values.
- Shortfall is visible as a separate cost signal, not as the normal market price.
