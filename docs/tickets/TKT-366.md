# TKT-366 — KSE Player Hour Scope Configuration

- Typ: Applikation
- Priorität: P1
- Status: Implemented

## Problem
Im KSE fehlte eine einfache Szenario-Option, um festzulegen, welche Stunden innerhalb jeder Runde von Playern aktiv bearbeitet werden dürfen.

## Ziel
Designer können pro Szenario definieren, ob alle Stunden, nur die erste, die ersten zwei, die ersten drei oder benutzerdefinierte Stunden-Offsets pro Runde spielbar sind.

## Umsetzung
- Neue Konfiguration `player_input` im Szenario-JSON.
- Optionen:
  - `all_hours`
  - `first_hour`
  - `first_two_hours`
  - `first_three_hours`
  - `custom_offsets`
- Optionales Flag `hide_non_editable_hours`.
- Validierung und Sanitizing im KSE-Backend.
- UI im KSE-Markets-Tab.

## Akzeptanzkriterien
- Designer kann die Hour-Scope-Option im KSE setzen.
- Die Werte werden korrekt gespeichert und beim Laden wiederhergestellt.
- `custom_offsets` akzeptiert nur gültige Offsets innerhalb von `round_span_hours`.
- Bestehende Szenarien ohne `player_input` bleiben rückwärtskompatibel.
