# TKT-383 — Result Payloads, Aggregation, And Market Structure For Zonal Pricing V1

- Typ: Applikation
- Priorität: P1
- Status: Planned

## Problem
Current result APIs and session aggregation focus on global price views and Phase 1 grid outputs. They do not yet expose the zonal price, spread, and congestion data required by the new V1 model.

## Ziel
Extend result payloads, aggregation, and market-structure responses so new V1 sessions can represent zonal prices and link metrics consistently.

## Umsetzung
- Extend `hourly_results` with zonal price, split, loss, and congestion fields.
- Extend `zone_results`, `link_results`, and `player_zone_info_by_player` with local price context and link information.
- Extend `market_summary` with average zone prices, split counts, max spread, and congestion/loss totals.
- Extend session aggregation helpers to summarize zonal pricing states coherently.
- Extend market-structure responses so synthetic previews and overview screens can represent zonal curves or zonal summary data.
- Use one canonical payload contract across all responses: `price_source` uses `uniform`, `zonal_split`, `islanded`, `shortfall_separate`; the global flag remains `zonal_pricing_active`, while player-local split state uses a separate field such as `player_zone_split_active`.
- Keep no-split payload behavior additive and non-breaking for visible values.

## Akzeptanzkriterien
- Split cases return complete zonal price and link metrics in the relevant payloads.
- No-split cases preserve current visible values while allowing additional informational zonal fields.
- Aggregation surfaces can report split hours, average zone prices, and congestion totals.
- Market structure can represent zonal preview data for V1 scenarios.
- Payload field names and enum values are consistent across hourly, zone, link, and player-facing responses.
