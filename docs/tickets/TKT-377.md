# TKT-377 — Engine Interzonal Routing And Grid Constraint Settlement

- Typ: Applikation
- Priorität: P0
- Status: Planned

## Problem
The current runtime uses a simplified zone payload and effectively collapses physical flow logic into one aggregate player zone. That is insufficient for Phase 1 interzonal modeling.

## Ziel
Implement deterministic zonal aggregation, routing, constrained-off generation, unserved demand handling, and consumer-only grid constraint cost allocation.

## Umsetzung
- Aggregate commercial generation and demand by actual configured zone.
- Derive player-side physical zone from `player_types[].zone`, with `general.player_zone` only as legacy fallback.
- Include zonal synthetic quantities from `environment.groups` and `market.consumer_mix` in hourly zone balances.
- Compute raw net positions per zone.
- Implement deterministic min-cost-flow routing over ATC-constrained links with per-link losses.
- Compute link utilization, binding links, and delivered energy by path.
- Compute constrained-off generation when surplus cannot be exported.
- Apply configured generator curtailment mode.
- Compute unserved demand and zonal extra costs.
- Allocate grid constraint cost only to consumers in the affected zone.
- Keep `grid_constraint_cost_zar` separate from imbalance and existing congestion revenue.

## Akzeptanzkriterien
- Engine supports deterministic min-cost-flow routing for 2 to 5 zones.
- Generator export constraints can reduce final deliverable dispatch without being booked as imbalance.
- Deficit zones create zonal extra costs that are allocated only to consumers.
- Profit and KPI calculations include `grid_constraint_cost_zar` as a separate component.
- Existing one-zone scenarios continue to work without behavior regressions.
