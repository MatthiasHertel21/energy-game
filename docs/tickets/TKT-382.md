# TKT-382 — Settlement And Dispatch Price Semantics For Zonal Pricing V1

- Typ: Applikation
- Priorität: P0
- Status: Planned

## Problem
Dispatch tracking, KPI construction, and detail rows currently assume one global `smp`. That breaks once split cases settle on local zone prices and shortfall must remain a separate cost component.

## Ziel
Move dispatch, settlement, and KPI logic to a consistent `system_price` / `zone_price` model while keeping one-zone and no-split outputs identical to the current behavior.

## Umsetzung
- Extend supply and demand dispatch tracking with `zone_id` and explicit zonal pricing context.
- Use local `zone_price` for producer revenue and consumer procurement in split cases.
- Keep current visible KPI values unchanged for one-zone and no-split cases.
- Keep shortfall as a separate residual cost path instead of replacing market prices.
- Apply `smp_multiplier` shortfall logic against `system_price` in V1.
- In the zonal path, stop computing `congestion_revenue_zar` via `cong_signal`; for split cases, replace it with a zero or omitted value and report real congestion only at link level via `congestion_rent_zar`. For no-split cases, preserve the existing `congestion_revenue_zar` value unchanged (non-regression).
- `atc_dispatch_cost_zar` must remain unchanged in one-zone and no-split cases (non-regression). In split cases, it should be set to zero; the corresponding settlement cost is already captured in the `zone_price` differential.
- Remove or guard the existing `_check('congestion_revenue_zar', ...)` engine consistency assertion so it does not fire for split cases where the value is intentionally zero.
- Update internal consistency checks and debug formulas to match the new price semantics.

## Akzeptanzkriterien
- Split cases settle consistently on local `zone_price`.
- One-zone and no-split cases remain identical to current KPI and ranking behavior.
- Shortfall cost remains separate from the normal market price.
- Detail rows do not mix global `smp` and local `zone_price` for the same business meaning.
- `congestion_revenue_zar` is zero (not heuristic) in split cases; unchanged in no-split cases.
- `atc_dispatch_cost_zar` is zero in split cases; unchanged in one-zone and no-split cases.
