# TKT-369 — Regression Coverage For Scoped Round Inputs

- Typ: Applikation
- Priorität: P1
- Status: Planned

## Problem
Das Feature greift in KSE-Konfiguration, Player-Submit-Logik und Result-Darstellung gleichzeitig ein. Ohne Guardrails drohen stille Regressions.

## Ziel
Die Hour-Scope-Logik wird durch gezielte Regressionstests und Smoke-Checks abgesichert.

## Umsetzung
- Backend-Tests für Hidden-Hour-Zeroing und Tradeable-Hour-Scope.
- Frontend-Smoke-Checks für sichtbare Stunden im Player.
- Abnahmeszenario mit Gerätevorbelegung, z. B. PV und nur erste Stunde pro Runde.

## Akzeptanzkriterien
- Hidden-Hour-Zeroing ist reproduzierbar verifiziert.
- Standard-Szenarien ohne `player_input` bleiben unverändert.
- Das PV-Beispiel liefert keine unsichtbaren Restgebote mehr im Rundenergebnis.
