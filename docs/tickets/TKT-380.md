# TKT-380 — KSE Validation And Zone Assignment For Zonal Pricing V1

- Typ: Applikation
- Priorität: P0
- Status: Planned

## Problem
The current scenario model still allows ambiguous zone assignment paths through `general.player_zone` or incomplete multi-zone configurations. That is incompatible with the simplified V1, where every player must play in exactly one explicit grid zone.

## Ziel
Enforce one unambiguous zone assignment per player for new V1 sessions and fail invalid multi-zone scenarios before pricing logic runs.

## Umsetzung
- Require `player_types[].zone` for all multi-zone scenarios.
- Remove `general.player_zone` from the V1 validation and execution path.
- Validate that every configured player type zone stays within `[1, zones]`.
- Reject multi-zone scenarios with missing or ambiguous player-type zone assignment.
- Reject `shared_market` scenarios that imply mixed zone assignment within the same effective player type.
- Update KSE labels, defaults, and validation messages to reflect the V1 rule set.

## Akzeptanzkriterien
- A multi-zone scenario without valid `player_types[].zone` values is rejected.
- The V1 path does not rely on `general.player_zone`.
- Invalid mixed-zone shared-market configurations fail fast with a clear validation error.
- KSE guidance and validation text describe the one-player-one-zone rule consistently.
